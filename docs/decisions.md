# Журнал рішень

Тут записані рішення, які ухвалені під час обговорення й змінюють або доповнюють системні документи.
Якщо документ системи суперечить цьому журналу, діє журнал, а документ треба виправити.

## Ухвалено (v1)

| # | Тема | Рішення | Де впливає |
|---|---|---|---|
| 1 | Платформи | ПК і телефон | UI з великими кнопками; ввід через `ContextActionService`; ціль вибирається тапом |
| 2 | Вибір цілі | Клац/тап по ворогу. Якщо цілі немає, а гравець вмикає здібність, обирається найближчий ворог. Сервер перевіряє, що ціль у межах дальності | `combat.md` |
| 3 | Персонажі | Один персонаж на акаунт | Профіль плоский (не масив персонажів): простіша схема й міграції |
| 4 | Респек | Статі й навички можна перерозподілити за ігрове золото. Клас назавжди | `stats-and-leveling.md`, `classes-and-skills.md` |
| 5 | XP і лут | Кожен учасник бою (хто завдав шкоди) отримує власний XP і власний кидок луту | `combat.md`, `items-and-rarity.md` |
| 6 | Обмін | Немає в v1. Предмети не передаються між гравцями | `items-and-rarity.md`: привʼязка при підборі не потрібна |

| 9 | Ресурс здібностей | Мана для мага (від `mind`), енергія для воїна й лучника (фіксована, швидка регенерація) | `combat.md`, `stats-and-leveling.md` |

| 15 | Анімації | Спочатку вбудовані (біг, стрибок, смерть). Анімації атак додаємо пізніше через таблицю «здібність → ID анімації» | Логіка бою не залежить від анімацій; потрібен власний акаунт чи група для завантаження |

## Зміни в коді, що випливають

- `MAX_LEVEL` = 50 (було 100 у демо-коді). Формула XP `round(100 * level ^ 1.5)` вже збігається з документом.
- Ідентифікатори класів `warrior`, `mage`, `archer` стабільні й не змінюються після релізу.
- Профіль зберігає `level`, `xp`, `allocatedStats`, `unspentPoints`, ID класу, ID відкритих здібностей, ID предметів. Похідні характеристики не зберігаються.

## Ще не вирішено

- Назва гри.
- Ціна респеку.
- Чи лишаємо в v1 м'який ліміт статів (після 40 очок приріст вдвічі менший).
- Конкретні ворогів MVP (3 типи): назви, рівні, поведінка. Заповнює разом з другом.
- Пакети npm для мережі й валідації (кандидати: `@rbxts/remo` + `@rbxts/t`) і для збереження (`@rbxts/profile-store`): перевіряю актуальність перед додаванням, кожен пакет окремо з обґрунтуванням.
